Overview Hollis Document Intelligence is a multi-tenant SaaS platform that uses Azure AI services to extract, compare, and analyse legal and commercial documents. This guide documents every Azure resource required to run the platform and provides step-by-step provisioning instructions including all required permissions, API access, and configuration values. Platform Components Component Technology Frontend React 19 SPA, Azure Static Web Apps, MSAL authentication Backend Azure Functions (.NET 8 Isolated Process) AI Processing Azure OpenAI (GPT) + Azure AI Document Intelligence (OCR) Storage Azure Blob Storage (multi-tenant containers) Data Store Microsoft Dataverse (Power Platform) — one environment per tenant Identity Microsoft Entra ID (multi-tenant app registration) 2. Architecture Summary The following diagram describes the high-level flow between components. ┌─────────────────────────────────────────────────────────────────┐ │ USER BROWSER (React SPA) │ │ MSAL login → Entra ID → Bearer JWT with tid + upn claims │ └──────────────────────┬──────────────────────────────────────────┘ │ HTTPS + Bearer Token ▼ ┌──────────────────────────────────────────────────────────────────┐ │ AZURE FUNCTIONS (Backend API) │ │ - JWT parsed → AAD Tenant ID extracted │ │ - Tenant looked up in Master Dataverse → TenantSettings │ │ - Per-tenant Dataverse connection created (ClientSecret auth) │ │ - Files → Azure Blob Storage (per-tenant container) │ │ - OCR → Azure AI Document Intelligence │ │ - AI → Azure OpenAI (GPT deployment) │ └──────┬─────────────────┬──────────────────┬──────────────────────┘ │ │ │ ▼ ▼ ▼ ┌─────────┐ ┌──────────────┐ ┌──────────────────┐ │ Blob │ │ Azure AI │ │ Dataverse │ │ Storage │ │ Doc Intell. │ │ (per tenant) │ └─────────┘ └──────────────┘ └──────────────────┘ │ ▼ ┌──────────────────────┐ │ MASTER Dataverse │ │ (hollis_tenant │ │ settings table) │ └──────────────────────┘ Key Design Points The platform is multi-tenant. Each tenant has its own Dataverse environment and Blob Storage container. The backend uses a single Service Principal (app registration) to connect to all Dataverse environments. Blob Storage uses DefaultAzureCredential (Managed Identity) with User Delegation SAS generation. JWT claims (tid) are used to identify tenants at runtime — no custom headers are trusted for tenant resolution. The frontend is a multi-tenant MSAL application using the /common authority in production. 3. Container Structure Each tenant has a dedicated container. Within a container, blobs are organised as: comparisons/{comparisonId}/documents/{fileName} ← original uploaded files comparisons/{comparisonId}/runs/{timestamp}/inputs/{fileName} ← run snapshots Permissions Summary Storage Blob Delegator Required on the storage account for Managed Identity to generate User Delegation Keys Storage Blob Data Contributor Required for the Managed Identity to upload, read, and copy blobs Scope Both roles assigned at the Storage Account level (not just container level) 8. Resource 6 — Microsoft Dataverse (Power Platform) Microsoft Dataverse is used as the primary relational database. There are two types of Dataverse environments in this architecture: Master Dataverse — holds the tenant registry (hollis_tenantsetting table). Tenant Dataverse — one per customer tenant, holds all comparison data. 8.1 Master Dataverse Environment The master environment is the first lookup point for every API call. It stores the mapping from AAD Tenant ID → per-tenant Dataverse URL, Blob container name, and subscription tier. Environment Type Production Dataverse environment (managed solution) Key Table hollis_tenantsetting Authentication Service Principal — ClientSecret auth (CLIENT_ID, CLIENT_SECRET, TENANT_ID) Access Level Application User with System Administrator or custom read/write role on hollis_tenantsetting hollis_tenantsetting Table Columns Column Name Type Description hollis_tenantid Text (Primary Name) Internal tenant key / business identifier hollis_tenantname Text Display name for the tenant hollis_aadtenantid Text Azure AD (Entra ID) tenant GUID — used as runtime lookup key hollis_alloweddomains Text Comma-separated list of permitted email domains hollis_dataverseurl Text (URL) Full URL of the tenant's Dataverse environment hollis_storagecontainername Text Blob container name for this tenant hollis_storageaccountname Text Azure Storage account name hollis_storagesassecretref Text Key Vault secret name for SAS token (reference only) hollis_subscriptiontier OptionSet Trial / Standard / Enterprise hollis_onboardeddate Date/Time Date the tenant was onboarded hollis_isactive Boolean If false, the tenant is blocked from logging in 8.2 Tenant Dataverse Environments Each customer tenant requires their own Dataverse environment with the Hollis managed solution installed. The Service Principal must be added as an Application User in each environment. Tenant Onboarding Procedure Follow these steps to onboard a new customer tenant to the platform. Step Action Details 1 Create Dataverse Environment admin.powerplatform.microsoft.com → Environments → New. Name: Hollis - &lt;TenantName&gt;. Type: Production. 2 Install Managed Solution Import the Hollis Document Comparison managed solution into the new environment. 3 Add Application User Settings → Users → Application users → New → Add backend service principal (CLIENT_ID) → Assign role. 4 Create Blob Container Navigate to the Hollis Blob Storage account → Containers → + Container. Name: tenant-&lt;short-name&gt; (lowercase, no spaces). 5 Get Customer AAD Tenant ID Ask the customer for their Azure AD Tenant ID (Directory ID) from portal.azure.com → Entra ID → Overview. 6 Create Tenant Settings Record Open the Master Dataverse environment → hollis_tenantsetting → New record → Fill all columns as per Section 8.1. 7 Set Subscription Tier hollis_subscriptiontier: Trial (initial) or Standard/Enterprise as contracted. 8 Set isActive = true hollis_isactive must be checked (true) for the tenant to log in. 9 Test Login Ask a user from the tenant to log in at the SWA URL. They should be redirected correctly and access data in their Dataverse environment. 10 Verify Blob Access Upload a test document and confirm it appears in the correct Blob container. 11 Upgrade Tier if required Update hollis_subscriptiontier to Standard to unlock Compare and Scoring modes. IMPORTANT: The tenant is identified at runtime solely by the Azure AD Tenant ID (tid claim) in their JWT. If a user logs in from a tenant not registered in hollis_tenantsetting, they will receive a 404 response. Always register the tenant BEFORE announcing the platform to users. 13. Troubleshooting Problem Symptom Resolution Tenant not found or inactive User receives 404 on login. Check hollis_tenantsetting in Master Dataverse. Verify hollis_aadtenantid matches the user's AAD tenant and hollis_isactive = true. Dataverse connection failed Functions log shows "Dataverse ServiceClient failed to connect". Check CLIENT_ID, CLIENT_SECRET, TENANT_ID in App Settings. Verify the Service Principal is added as Application User in the target environment. Unable to determine tenant from Bearer token API returns 401 Unauthorized. The JWT does not contain a tid claim. Ensure MSAL is acquiring tokens scoped to the backend API (api://... scope), not Microsoft Graph. BlobBaseUrl missing Functions throw exception on upload. Check BlobBaseUrl is set in Application Settings and matches the format https://&lt;account&gt;.blob.core.windows.net (no trailing slash, no container name). SAS generation fails (403) GenerateUserDelegationSasAsync throws. The Function App Managed Identity is missing the Storage Blob Delegator role on the storage account. Check IAM assignments. Azure OpenAI quota exceeded AI extraction returns 429 Too Many Requests. Increase the tokens-per-minute quota in Azure OpenAI Studio → Deployments → Manage quota. Document Intelligence 400 error OCR fails for a specific PDF. The PDF may be password-protected, corrupt, or exceed page limits. Check the Document Intelligence logs in Azure Monitor. CORS error in browser Frontend gets "Access-Control-Allow-Origin" error. Add the SWA URL to the Functions App CORS allowed origins. Ensure "Enable Access-Control-Allow-Credentials" is checked. Trial tenant accessing Compare mode Backend returns 403 Forbidden. This is expected behaviour. Update hollis_subscriptiontier to Standard in the Master Dataverse to unlock full modes.
